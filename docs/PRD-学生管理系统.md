# 学苑 · 高校学生管理系统 PRD（V1）

## 1. 背景与目标

高校教务在学期内需要一条清晰闭环：**建组织 → 建学籍 → 开课 → 选课 → 查课表 → 出报表**。V1 把这条链路做成可运行的管理系统，界面克制、规则明确。

**产品名：** 学苑  
**用户：** 教务管理员、教师、学生

## 2. 范围

**包含**

- 账号与角色权限（管理员 / 教师 / 学生）
- 学院、专业、行政班
- 学生档案与学籍状态
- 教师档案
- 课程库、学期教学班
- 学生选课 / 退选，教务强制加退选
- 容量校验、时间硬冲突
- 课表、统计报表与 CSV 导出
- 学籍变更与强制加退选审计日志

**不包含（后续版本）**

- 成绩、绩点、先修课、抽签选课
- 考勤请假、收费、宿舍、招生
- 原生移动 App

## 3. 角色权限矩阵

| 能力 | 教务管理员 | 教师 | 学生 |
| --- | --- | --- | --- |
| 组织 / 学籍 / 教师 / 课程库 | 读写 | 无 | 无 |
| 开课与名单 | 读写 + 强制加退选 | 只看本人授课 | 无 |
| 选课退选 | 强制操作 | 无 | 窗口内自选 |
| 课表 | 全校 | 本人授课 | 已选课程 |
| 报表导出 | 有 | 无 | 无 |
| 个人档案 | — | — | 只读 |

登录名：管理员 `admin`，教师用工号，学生用学号。

## 4. 关键业务规则

1. 仅「在读」学生可选课。
2. 教学班已选人数不得大于容量。
3. 同一学生同一学期，星期与节次重叠视为硬冲突，禁止选课。
4. 学生选课/退选必须在当前学期选课窗口内；教务强制加退选不受窗口限制，但必须写审计。
5. 学籍状态变更写审计。

## 5. 实体

学院、专业、行政班、学生、教师、课程、学年学期、教学班（开课）、选课记录、用户、审计日志。

## 6. 非功能

- 演示数据可重置。
- 数据保存在浏览器本地，便于单机演示。
- 选课校验在写入前完成，避免超选与冲突。

## 7. 验收要点

- 三个演示账号可分别进入对应导航，越权路由被重定向。
- 学生选满「离散数学 B班」（容量 2）后第三人失败。
- 选择与已选课程同时间的教学班失败。
- 教务可按学号强制加选，日志可在总览看到。
- 报表可导出 CSV。
